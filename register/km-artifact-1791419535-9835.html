This register sits above all four. It says which questions each layer has to answer and where the answers can come from.

Kinds of question

  • class: what the product class is and does. Learned from the reference platforms.
  • slot: where the platform lets an outside party plug in (payments, carriers, tax, channels, apps, agents). The slot belongs to the product.
  • world: what fills a slot, or the rules around it, in a given market. Needed when the slot is filled; it does not define the product.
  • build: how to engineer an instance. Not visible from outside.
  • intent: Sharrwah's own decisions.
  • method: about the knowledge work itself.

When a question is needed

  • spine: to build the capability map and glossary now.
  • model: before the area's domain model is written.
  • slice: before the area's first build slice.
  • launch: before merchants depend on it.
  • later: when the area comes up.

Risk is the cost of getting the answer wrong: high means expensive to change later, so it is answered first within its stage.

Working a question with an agent

  1. Give one question id, its listed evidence, the allowed source types, and the stop rule for its facet (README).
  2. Ask for claims, each with the evidence id and path it rests on, a confidence, and any disagreement found. Nothing it did not open.
  3. Have a second agent re-derive the claims from the bytes alone before they are accepted.
  4. Record the answer in the claims layer and set the question's status. Decisions go to the founder as ADRs.

Rules

  • Pointers say where to start looking. They come from the evidence or the repositories' own notes, and they are not answers.
  • The Evidence column only says which repositories the cited evidence is in; tools/check.py enforces it.
  • Labels under Areas are each platform's own words.
  • The TSV files are the source of truth; this page is built from them by tools/render.py.
