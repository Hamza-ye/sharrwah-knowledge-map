# Intro to App Snippets

**App Snippet** lets you extend any merchant store with custom **JavaScript** from the App Snippets section in the [Salla Partners Portal](https://portal.salla.partners). The Snippet is injected automatically when your app is installed. Salla uploads your snippet as a `.js` file to its CDN and serves it on stores that have your app installed, no deployment or hosting needed on your end.

The editor has been rebuilt from the ground up. What was once an HTML field is now a dedicated JavaScript editor, which means raw markup injection is gone, replaced by a CDN-backed pipeline. Save uploads your snippet to the CDN. You can mock public App Settings values and click **Refresh preview** to test configuration on your demo store without re-saving, but any change to the JavaScript itself requires **Save** before it appears in the preview.

In this article, we will cover how snippets are injected, how to work with store parameters, and walk through building a live chat integration using tawk.to.

:::danger[Migration Required]


Migrate your App Snippet before **5 September 2026**, then publish your updated application through the [Salla Partners Portal](https://portal.salla.partners).

**Migration Grace Period:** **5 August 2026 – 5 September 2026**
:::

## Overview

App Snippet lets you inject custom JavaScript into your merchants' stores. The `.js` file is uploaded to Salla's CDN when you hit **Save** in the editor. Once a merchant installs your app, Salla injects that CDN-hosted file into their store automatically.

:::warning[]

App Snippet now requires valid JavaScript, no raw HTML or JSX. If you still have legacy HTML snippets, open them in the new editor, rewrite them as JavaScript, and **Save** to migrate to the CDN pipeline. Migration is required to stay supported on the platform; legacy inline snippets will not receive future improvements.

![image.png](https://api.apidog.com/api/v1/projects/451700/resources/378590/image-preview)
:::

If you inspect a store page source after installation, you will find a `<script src="...">` tag pointing to a Salla CDN URL, that is where your snippet is being served.

Both **Public** and **Private** apps support App Snippet. Scroll down in your app details page on the [Partners Portal](https://portal.salla.partners) to find the App Snippet section.

## Add a New Snippet

<Frame caption="Add new snippet button">

![image.png](https://api.apidog.com/api/v1/projects/451700/resources/378596/image-preview)
</Frame>

When creating a new snippet, the editor presents you with:

| Field | Description |
|---|---|
| **Snippet Name** | A label to identify your snippet in the portal |
| **JavaScript Editor** | Write valid JS code here, HTML and JSX are not accepted |
| **Preview Screen** | Live preview of how your snippet renders on a demo store |
| **Store Parameters** | Reserved variables accessible via `salla.config.get()` |
| **Mock values** (Settings parameters only) | Set test values for public `app.*` fields to preview configuration on your demo store without re-saving. Store and user parameters use real data from the selected demo store. |
| **Action Buttons** | **Reset**, discards unsaved changes and restores the last saved content. **Refresh preview**, reloads the demo store iframe and applies current mock values (requires valid JS and a selected demo store). **Save**, uploads or updates your snippet on the CDN. |

<Frame caption="The new App Snippet JS editor">

![image.png](https://api.apidog.com/api/v1/projects/451700/resources/378601/image-preview)
</Frame>



:::note[Preview requirements]
Before using the preview:
- Select a demo store with your app already installed.
- Save the snippet at least once so it is available on the CDN.
- Mock values apply only to public `app.*` settings; store and user parameters use live demo-store data.

Snippets are injected in `<body>`. Maximum script size is 50,000 characters.
:::

## JavaScript Rules and Guidelines

:::warning[]
Violating these rules will result in rejection during the app review process.
:::

<CardGroup cols={2}>
  <Card title="JavaScript Only" icon="material-two-tone-javascript">
    Your snippet must be valid JavaScript. HTML and JSX are not accepted.
  </Card>
  <Card title="No iframes or Embeds" icon="material-two-tone-block">
    The use of `iframe` and `embed` tags is strictly prohibited for security reasons.
  </Card>
  <Card title="No History Manipulation" icon="material-two-tone-history_toggle_off">
    Functions like `history.replaceState()` are strictly prohibited for security reasons.
  </Card>
  <Card title="No Dynamic Code Execution" icon="material-two-tone-code_off">
    Avoid `eval()` and similar dynamic code execution, snippets using them will be rejected during app review.
  </Card>
  <Card title="Clean Up Intervals" icon="material-two-tone-timer">
    If you use `setInterval()`, always conditionally call `clearInterval()` to prevent memory leaks and repeated background execution.
  </Card>
  <Card title="Minimal Logging" icon="material-two-tone-speaker_notes_off">
    Avoid `console.log()` for general debugging. Reserve it for cases where something might genuinely go wrong.
  </Card>
  <Card title="Submit Readable Code" icon="material-two-tone-find_in_page">
    Share deobfuscated code separately when submitting for review, for faster feedback.
  </Card>
  <Card title="Keep a Live Demo Store" icon="material-two-tone-storefront">
    Maintain at least one demo store with the snippet running so the review team can test it.
  </Card>

</CardGroup>

  <Card title="Use innerHTML Carefully" icon="material-two-tone-warning">
    Use `innerHTML` responsibly. Do not use `body` as a direct reference.
  </Card>
  
  :::tip[Publish Your Changes]

Before publishing, make sure you have:

- ✅ Tested the snippet on a demo store.
- ✅ Verified all functionality works correctly.
- ✅ Submitted a new app publish request.

For detailed instructions, see the [**Publishing Your Application**](https://salla.dev/blog/standards-salla-apps-publications/) guide.
