# Method

**What this folder is:** the scripts the plan uses. Run each with `python3 -I`.

| Path | What it is |
| --- | --- |
| `capture/` | The tools that make the copies in `evidence/`: raw fetch, browser render, manifest, OCR, and text from pages the founder saved. Its README says how to run them. |
| `check_concern_map.py` | The checker for Q1's output: the six files per platform, ids and references, placement values, and every quote against its source. |
| `q1_gaps_report.py` | Writes `studies/concern-map/gaps-to-close.md` from each platform's gaps. |
| `q1_held_check.py` | Checks every Q1 gap against what is held, and re-routes the gaps that went to the founder (Stage 0). |
| `q1_list_joins.py` | Candidate statements for Q1's Salla and WooCommerce re-passes. |
| `q1_shopify_joins.py` | Candidate statements for Q1's Shopify re-pass. |
| `q1_side_by_side.py` | The combined Q1 map: matched concerns side by side, each platform in its own words. |
| `build_yemen_cases.py` | Builds Stage 1's axes, constants and cases from its pass 2 files, by the rules of `studies/yemen-cases/brief.md`. |
| `test_build_yemen_cases.py` | Tests `build_yemen_cases.py` against those rules. |
| `join_pass1.py` | Joins Stage 1's pass 1 parts. |
| `join_pass2.py` | Joins Stage 1's step 2b files for the build. |
| `check_yemen_cases.py` | Checks Stage 1's output against its brief. |
| `check_subject.py` | Checks a subject's files against its briefs (Stages 2 and 4), with the subject's own bullets (its `bullets.tsv`). |
| `seed_subject.py` | Copies what is already recorded for a subject's concerns, in the concern map and in earlier subjects, into the subject's folder for its phase A agents (Stage 4, "from what is recorded"). |
| `subject_slice.py` | Cuts a subject's phase A files into one slice per root decision, for the agents that work on one decision each, and prints the part of a slice an agent asks for. |
| `merge_slices.py` | Joins the files the agents of one root decision each wrote into the subject's own files, and refuses ids outside a decision's range, a bullet outside it, or more variation points than its cap. |
| `second_pass_list.py` | Writes phase B's second-pass work list per root decision: first the rows gap-closing worked, to revisit, each with its leads, the statements gap-closing found for the point under its bullet; then the statements still to place, from the checker's `unplaced.tsv`, but those leads; then the statements `b/second-pass.md` lists, to read again or to note. `--check` lists the revisit, reread and note tasks without an outcome in their root decision's ledger, `b/<root decision>/done.tsv`. |
| `round_tasks.py` | After a round of gap-closing or an audit adds statements, appends phase B's tasks for that round to the real work lists: the new statements to place, the rows naming a gap since settled, and every revisit whose leads have no other task. |
| `variants_edit.py` | Edits one root decision's phase B files row by row, for the second pass: joins statements to a variant, taking its kind and scope again from all of them; adds, replaces or removes a variant, with the next free id of the decision's range; records a task's outcome in the ledger; adds a platform's words to a point's `x_words`, or a note to a point or a row. It refuses an excerpt not in its statements, a statement outside the slice, and an unknown basis. |
| `point_view.py` | Prints what phase C reads on a variation point: each platform's rows in the brief's three groups, with each row's excerpt and evidence, each statement's kind, scope and release marker, the statements under (h) that condition them, and what a gap asks or an absence says. `--records` prints statements, gaps and absences whole by id, with their kind. |
| `analysis_edit.py` | Writes, shows and checks one root decision's phase C files from S-02 on: a point's keys (the answer each row gives), and from them what each platform does on each key (gives, lacks, open, not stated) and the cause the mechanical tests give; a row per key (`answers.tsv`) and per point (`points.tsv`); and notes under a part's heading. It refuses what the brief's rules exclude, such as a cause outside its tags, a rule outside its tables, a founder decision judged cheap, or `no difference` for a key some platform doesn't give. |
| `schema_type.py` | Prints a GraphQL type in full from a schema the observed repositories hold, with the citation a quote from it takes. |
| `held_index.py` | What observed-sa, observed-sh and this repository's capture runs hold, by address, and in what readable form. |
| `quote_check.py` | Is a quote found, word for word, in its cited source, and, for a web page, in the page as it renders or only in its source? Shared by the checkers, and run alone to test a statement or a quote before it is written, a batch of them at once, or to print a source's text as the checker sees it. |
| `source_kinds.py` | The kind of a cited source, assigned by rule (`PLAN.md`, section 6, the test form). |
| `warc_text.py` | Prints one record of a fetch archive held in git. |
| `corpus_search.py` | Searches a platform's held text in every language it holds, for a claim of absence (`PLAN.md`, section 6). |
| `runs_corpus.py` | The observed repositories' runs, as documents for `corpus_search.py`. |
| `count_tokens.py` | Counts the tokens an agent run processed, once per request (`PLAN.md`, Stage 4). |
| `check_register.py` | Checks every citation in a subject's decision register: ids, paths at a commit, and that each cited line holds what the citation names. |
| `register_items.py` | Lists the founder items of a subject's phase C that its register answers in no row, or in two: every item must be answered, or moved to another subject, exactly once. |
| `check_yemen_row.py` | Checks a subject's Yemen row against its brief: columns, a row for every founder decision, `exists` and what backs it, each Stage 1 id in its file, and no product gap that names Yemen; lists each cited id that Stage 1's `corrections.md` corrects, for the coordinator to read against the row. |
| `check_scenario_walk.py` | Checks a subject's scenario walk against its brief: columns, every founder decision and engineering constraint walked through the three scenarios, the costs and flags allowed, a reason for every option closed, and each cited id the subject's. |
| `check_report.py` | Checks each quote in a report against the line its pinned citation names. |
| `class_slice.py` | Prints what a part of the class's model reads, compactly: the seed's areas, a domain's concerns from `studies/class-model/scope.tsv`, statements by key, a search over a platform's statements, Q1's matches, gaps and unplaced entries, a domain's model so far, the statements no cell cites, and for each capability a platform's candidate statements, found by the terms the other platforms' cells use (`studies/class-model/briefs/B-extent.md`). A statement's key is `concern_id/placement/first_cite_id`. `caps` searches every domain's capabilities, so a part can check that no other domain holds what it is about to add.  `key` also reads a landed subject's statement by its id (S01-SA-104), which only the coordinator's amendments from the subjects' points cite; `check_class_part.py`, `class_merge.py` and `km_page.py` resolve such keys too. The held pass's entries are read from `held/<platform>/entries.tsv` and, for its second stage, `entries-s2.tsv` (an S2 entry's identifier is its page's title or item's id, and its citation its own source, locator and quote), so the model's tools accept the second stage's ids. |
| `check_class_part.py` | Checks `scope.tsv`, or one part of the class's model (anchor, mapping, back-fill or amendment), against its brief and the domain's model so far: headers and tokens, ids and numbering, every concern landed once, a landing by a Q1 match beside the match's other concerns, one cell per capability and platform, every key found, every term in a cited statement, and each ruling on an unclear candidate against where its concerns landed. Flags for the reviewer what it can't rule on: a `none-held` cell whose terms match statements, `core` resting only on API objects, every `own-service`, a statement cited from a domain that doesn't name the part's. Writes each cell's places, scopes and gaps into the part's `derived.tsv`, and the qualities' scopes into `derived-qualities.tsv`. |
| `class_kinds.py` | Computes each capability's count and kind from the parts' cells, by the plan's one rule (Stage 4A): the count of platforms that place it in their core or as their own service; `class` where it is at least one, `slot` where every platform that shows it leaves it to third parties, otherwise `open` for review. A platform with nothing held is never counted as lacking it. |
| `class_merge.py` | Merges the parts of the class's model into `studies/class-model/merged/`, and checks what no single part can: each concern landed once across domains, each capability id and cell once, each ruling again on all its domain's parts, a statement counted as core in two domains (by its statement id, under whichever concern's key it is cited), a clean landing whose shared statement is cited in another tree, and capabilities of two domains that may be one. Writes the kinds, and architecture's index of each capability's data, events and deciding statements, exact where cited and by landing otherwise. For the qualities pass (`studies/class-model/briefs/QL-qualities-design.md`, section 6.2), once `qualities/labels.tsv` exists, it carries each quality's scope from the parts' `derived-qualities.tsv`, gives every row a stable `row_id` (`QR-` and 10 hex digits of sha1 of its cap_id, platform, quality, value and key), adds the platform-wide rows of `qualities/platform.tsv` (part `QL`), joins the labels, and writes `merged/qualities.tsv` (labels quality and other, and rows not yet settled) and `merged/terms.tsv` (the plans' terms); before that file exists, `merged/qualities.tsv` is written exactly as before. An unlabelled or unsure row, or a label naming no row, is a flag, and a problem with `--labels-complete`, which the coordinator passes once the labels' review (QL-L) is done. |
| `km_page.py` | Generates the Knowledge Map's page, rebuilt (Stage 4A; the founder, 30 October), from the model's merged files, the seed's areas and source types, the concern map's citations and Q3's check, with every capability, cell and evidence row linked to its row at a pinned commit. It refuses when the merged files differ from that commit. `--draft` marks a page built before every domain and platform has run. Once the qualities are labelled (the qualities pass), each cell lists its qualities by kind, its other values, and "The plans' terms (n)" folded under them, and the view "Qualities by kind" sets the 16 kinds against the five platforms from `merged/qualities.tsv` and `qualities/coverage.tsv` and `outcomes.tsv` (which it also requires committed): found, with its values; "searched, not found at <commit>"; "not held"; or "not read yet", never absent. |
| `km_page_template.html` | The page's template, in the seed page's design: edit it, never the generated page. Its "Qualities by kind" tab and each cell's qualities and folded terms are the qualities pass's. |
| `land_points.py` | Lands the subjects' variation points on the class's model (Stage 4A, "The subjects' points"; the brief `studies/class-model/briefs/P-points.md`): `leads` and `show` trace each point's statements to the concern map, by the statement it comes from or the page it was read on, and from there to the cells that cite it and the capabilities its concern lands in, beside the capabilities that hold the point's own terms; `check` checks a batch's file in `studies/class-model/points/`, the register rows each point names, and the conflict and status rules. |
| `q3.py` | Q3's check for what the class's model misses (Stage 4A; the brief `studies/class-model/briefs/Q3-check.md`): builds the 260 rows, read for their id, question and `needed_by` only, from the commit `PLAN.md` links; lists each area's capabilities once and each row's leads; `where` says which cells cite a statement and where its concern lands, by statement id; `check` checks a batch's file, computing `bundles` and `wrong time` from the rules; `unasked` lists the capabilities no covered row names. |
| `q3_misses.py` | Q3's candidate misses, checked against what the evidence repositories hold, guides and indexes first (the brief `studies/class-model/briefs/Q3-misses.md`): `misses` lists them with their rows, and `check` tests a batch's lines and every quote of its statements against its source. `PARTS` holds each miss's parts, which the held pass's second stage reads one by one (`s2_held.py`), and each rest prints under the label that it is about the concern map only. |
| `held_vs_read.py` | What the evidence repositories hold against what the class's model read, per platform: structures (held, cited, their items and the items cited), addresses and runs; writes `studies/class-model/held-vs-read.tsv` (the founder, 30 October). |
| `held_entries.py` | The held pass (the brief `studies/class-model/briefs/H-held.md`): `registers` and the coordinator's `held/selection.tsv`; `build` lists every entry of the selected self-descriptions that the model hasn't read, rendered from the fields the platform states and cited at the repository's commit; `batches`, `show`, `earlier` and `check`. The selection's rule language is set out at the head of the script; `files:`, `label:`, `prune:`, `wrap:`, `pick:`, `name:`, `merge:`, `latest:`, `group:` and `long:` were added for Shopify's page data, versions and prose on 31 October, and `nodes:` for Salla's settings centre, whose items it joins to their sections' answers. `batches --alone N` gives a structure of N entries or more batches of its own, so its batches wait on no other structure's, and a short batch joins the one before it. `earlier` prints, for each entry of a batch, the lines of the platform's other batches that cite the entry's own keys (its address, route or app name, translation key, or quoted label), grouped by capability and support. `show --candidates` prints each entry's leads, in the same order on every run: capabilities whose cited statements share its identifiers, whose terms its values or a route's path segments hold, or whose names share its words (`name:`). `cells --platform P CAP...` prints each named capability's cell compactly: its name, parent and note, what the cell holds and places, its terms, reading and evidence rows' reasons. For a bundle route structure (Salla's `dashboard-app-routes` and `portal-app-routes`), `show` prints each entry's items, every one with its app and path, with their keys and the bundle's archive record, and `show --code N` the bundle's code at each item's path. `makers --platform P NAME...` prints the held entries that name an app in one sentence with a maker's cue ('we’ve added … to X', 'our', 'first-party', 'from Shopify'), with the lines their batches gave them (the rulings after SH-37 and SH-55). The second stage's entries (`entries-s2.tsv`, structure `second-stage`, landed by `s2_held.py`) are read by `check`, `show`, `earlier` and the leads; `build` never writes that file nor drops its ids, and `batches` cuts only `entries.tsv`. `check` tests each second-stage entry's text against its source at its locator, its repository and its commit (one the batch's notes name on their first line, or the HEAD), a miss being a problem. It accepts the qualities pass's placement `quality` (a `QL-<XX>` batch, `method/ql_qualities.py`): a capability of the merged model, supports `shows` only, one quality `<what>: <value>` that is not a mark of inclusion, no terms or filler; its `CHANGES` lines print it as a quality, and a `QL-` batch's entries are tested at their sources as the second stage's are. |
| `held_router_gates.py` | The held pass, Shopify's admin router: names each route's ancestors' gates on the store in the reading of every line of a batch that doesn't yet name them (the ruling after SH-8). The coordinator runs it with `--apply` after each router batch. |
| `held_productlist.py` | The held pass, Shopify Editions: places Winter '23's Product list (SH-52), whose entries repeat the edition's solution items, by SH-51's rule E18. Each entry takes its item's first line, the item found by its collection and its order, and collections whose counts differ are left for a match by heading. Run with `--write`. |
| `held_role_permissions.py` | The held pass's SH-5 (after SH-4): each of a role's permissions in Shopify's `admin-role-permissions` whose handle the permission tree holds takes that permission's line from SH-3 or SH-4, its access level in `reading`; it cuts SH-5 to SH-7 again, the matched entries in SH-5 and the rest, most of them the POS role's, in SH-6 and SH-7 for agents. |
| `held_tracking_carriers.py` | The held pass's SH-102 (the re-plan of 31 October): each of the 203 options of Shopify's return form tracking carrier field takes the list's line, CM-SHP-017 `core`, its carrier the filler, since the cell cites the value list as a whole; it cuts SH-101 and SH-102 again, the carriers in SH-102 and the `tinker-tools` entries beside them in SH-101. |
| `held_router_changes.py` | The held pass's SH-19 (the re-plan of 31 October): each of Shopify's `admin-router-changes` whose route the router batches placed, and whose eligibility is the same before and after, takes the route's own lines (a removed route as `shows`); the other changes are left for an agent in the same batch. |
| `held_tinker_tools.py` | The held pass's SH-101 (the re-plan of 31 October): the Tinker app's tool catalog, each tool card and the label repeating its name on the new thing Tinker by Shopify, the screen's own frame `out`; it cuts SH-100 and SH-101 again, the tinker-tools entries in SH-101 and the other structures' entries beside them in SH-100. |
| `held_mobile_repeats.py` | The held pass's SH-80 to SH-84 (the re-plan of 31 October): the Shopify mobile app's screens as view nodes, where the same node recurs on each screen that shows it. `--cut` puts each node's first occurrence in SH-80, SH-82 and SH-83, for agents, and the repeats and bare layout nodes in SH-81 and SH-84; `--apply`, once the agents' batches are checked, gives each repeat its first occurrence's lines and each bare layout node `out`. |
| `held_scope_apis.py` | The held pass's SH-24 and SH-104 (the re-plan of 31 October): the Dev Dashboard's scope picker, where each resource heading has the API that grants its scopes under it. `--cut` leaves SH-24 the headings and the picker's other entries, for an agent, and puts the API labels whose heading is a held entry in the new batch SH-104; `--apply`, once SH-24 is checked, gives each label its heading's lines (SH-23's R23.10; E157), the API its term. |
| `shopify_arabic_names.py` | Shopify's amendment (the founder's note of 31 October): each Shopify name in a capability's definition, with the Arabic that observed-sh's vocabularies (the admin's, then checkout's, then shopify.com's) pair with its exact English by Shopify's own keys, the most frequent rendering first and every key cited; a name with no exact twin is left for a reader. `--write` writes `studies/class-model/names-ar.tsv`. |
| `held_plan_frame.py` | The held pass's SH-91 (the re-plan of 31 October): the admin's plan page on ibx5bt-xy as read from `<body>`, so its last entries are the admin's frame. By SH-89's R89.9 the main navigation, the keyboard shortcuts and the UI strings are `out`, the trial banner takes SH-3's line 9 and 'Plus+' the Plus card's line; any other entry stops it, for an agent. |
| `held_amend.py` | The coordinator's amendments from the held pass: each checked placement becomes evidence in the part that holds the cell, with the cell's reading extended; `plan` shows what `apply` writes. `--batch B` (repeatable, such as `--batch S2-ZD`) plans only those batches, with their rows of `s2-keys.tsv` (a statement already in the concern map, as an evidence row) and `s2-outcomes.tsv`; `apply` then refuses a part only where the same capability, platform and entry are already in its evidence, writes the cell's reading in the second stage's words, and, for each cell the batch leaves holding nothing, writes into its reading and `searched` what the second stage read and searched, at its commits, and its outcome (the coordinator's decisions 2 and 3, `briefs/S2-held-design.md`). For the qualities pass's batch `QL-<XX>`, each `quality` line, and each of its rows of `s2-keys.tsv`, writes its quality row into the part that holds the cell, with a `shows` evidence row only where the cell doesn't already cite the key (a cell that held nothing becomes held, its reading naming the quality); it refuses only a quality row (cap_id, platform, quality, value, key) already in the part's `qualities.tsv`. It tests every part before writing any. |
| `s2_held.py` | The held pass's second stage (the brief `studies/class-model/briefs/S2-held.md`, its design `briefs/S2-held-design.md`). For the agents: `cells`, `leads` and `misses` print a part's cells holding nothing, the held pass's leads for it (`--held` the ones naming only held cells) and its misses with their parts; `check` tests a part's rows and notes, every quote against its source at its locator and the part's commits. For the coordinator: `parts --write` writes `held/s2-parts.tsv`, `mark` sets a part checked, `misses-join` and `check-misses` the misses' decisions across the platforms, and `land --platform P` lands the checked parts into the batch `S2-<XX>` (or a correction batch `S2-<XX>-R<n>`): `entries-s2.tsv`, the batch's files, `s2-keys.tsv`, `s2-outcomes.tsv` and `s2-captures.tsv`. `--help` prints its usage. |
| `ql_qualities.py` | The qualities pass (the brief `studies/class-model/briefs/QL-qualities.md`, its design `briefs/QL-qualities-design.md`): what the platforms state on how well, how safely, or within what bounds they do what they do, in 16 kinds and 44 asks. For the agents: `asks --part P [--left]` prints each kind with its default capabilities' cells, the model's rows labelled as it, and the places `qualities/sources.tsv` names, then its asks; `check --part P` tests a part's rows and notes, every quote at its source and the part's commits by `s2_held.py`'s tests, every value inside its quote, and refuses a price or a plan's term as a quality. For the coordinator: `parts --write` writes `qualities/parts.tsv` (seven parts), `mark` sets a part checked, `land --platform P` lands a platform's checked parts, after its second-stage batch, into the batch `QL-<XX>` (or `QL-<XX>-R<n>`): `entries-s2.tsv` by the second stage's ids, `placements-QL-<XX>.tsv` (placement `quality`), `s2-keys.tsv`, `qualities/platform.tsv`, `labels.tsv`, `outcomes.tsv`, `captures.tsv` and `coverage.tsv`; `labels propose [--write]`, `review`, `apply-review`, `check` and `clear --rule R` label the model's quality rows as qualities, the plans' terms or other, by the design's rules Q1, T1, T2 and T3 and the review. It imports `s2_held.py`'s source and quote tests and its entry ids. `--help` prints its usage. |
| `held_calibrate.py` | Compares a calibration batch of the held pass with the reviewed placements of the same entries: per entry, the capability and supports pairs missing, extra or with another supports, and which would change the model. |
| `review_select.py` | Selects, by risk, what the final review of the extent reads (the brief `studies/class-model/briefs/R-extent.md`, its design `R-extent-design.md`), once, after the last landing before it: one item per cell, per capability, or per question that is neither, with every reason it was chosen. From the merge: a kind or a count it hinges on, a none-held with leads (but those the held pass's second stage read), a join on role or a homonym, a maker reading, a scope, strained landings, the merge's questions (`one capability?` by shared terms), every coordinator row and note, the parts' leads, Q3's rows, the subjects' points. From the held pass on: every cell whose counting changed since the merge of 30 October (`--since 9d204b46`), every cell of a capability made or widened since, a seeded sample of the held lines of each high-weight ruling of `reports/GM-rulings.md`, the coordinator's corrections and alignments on held lines by risk, the held notes' leads, the second stage's leads naming only held cells by risk and its notes on held cells (S2-R2), the qualities pass's notes on a placement (QL-R8), the omission review's findings that don't land with a seeded tenth of its `held` verdicts, and a seeded line of every batch; a seeded sample of every part, leaving out what the omission review sampled; in batches of 30 per share. It prints each reason's count and an estimate (an assumption). `--out` writes elsewhere, for a test. `check --share --batch` checks a reviewer's coverage file; `rates` counts the verdicts by reason, and the omission review's own miss rate. |
| `check_surface.py` | Searches the working files for the framings of the work that is now history, and fails where one appears outside the places allowed to name it (`PLAN.md`, risk 14). |
