# Review of first decisions 6 to 10

*Scope: a review of `first-decisions.md` §6–§10 only, as the coordinator relayed from the founder on 1 November 2026. No alternatives. I checked every quote and count in those sections against the evidence at `04de369d`, and checked each practice citation on the web on 1 November 2026.*

**Summary for the founder**
1. **One API (6):** the title and question assume a single contract, but Shopify runs several, on one version calendar. One claim (*the admin uses the same API*) goes beyond its cited line. The citations are real. The ID scheme is needed now; the version calendar can wait.
2. **Money (7):** the question is neutral and the citations are real, though Shopify's currency list is wider than ISO 4217. Needed before the first area that holds an amount.
3. **Language (8):** the question is nearly neutral. The citations are real, though Shopify's storefront languages are a closed list of codes, not BCP 47 tags. Needed now, by Shopify's own account of the cost of waiting.
4. **Events (9):** the question merges three mechanisms that Shopify keeps apart. Its *one shared shape* isn't in Shopify's evidence, and one claim has no pinned link. The citations are real; NIST's is about security logs. Recording changes is needed now; delivering them can wait.
5. **Custom data (10):** the question assumes Shopify's answer and goes further than Shopify does (31 types, not every resource). The citations are real. Only the shared place on resources is needed now.

## 6. One API for every area

1. **Wording.** The title and the question (*What single, versioned contract does every area expose (to the admin, apps and storefronts alike)*) assume one contract. Shopify's evidence shows several: "admin, customer, storefront, partner, payments-apps, 13 Functions APIs" ([REGISTER L23](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/REGISTER.tsv?plain=1#L23), *the capture's* description). The storefront has its own root: "The entry point for all Storefront API queries." ([storefront schema L310](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/storefront-graphql-schema/2026-10/items.jsonl?plain=1#L310)). **Reading:** a neutral question would be *through which contract or contracts do areas expose their reads and writes, how do those contracts change over time, and how is an object identified across areas?*
2. **Practice citations.**
   - Medjaoui, Wilde, Mitra, Amundsen, *Continuous API Management*, O'Reilly, November 2018, https://www.oreilly.com/library/view/continuous-api-management/9781492043546/. Real. Its contents treat change (chapter 5, *Continuous API Improvement*) and versioning (one of the *eight Vs* of an API landscape), as the file says. I saw the publisher's contents list through a web search, not the full text.
   - Berners-Lee, Fielding, Masinter, *Uniform Resource Identifier (URI): Generic Syntax*, RFC 3986, January 2005, https://www.rfc-editor.org/rfc/rfc3986. Real. Section 1.1 says "URIs have a global scope and are interpreted consistently regardless of context"
   - Shopify itself names a different basis for its IDs, which the file doesn't cite: "Enables global object identification following the Relay specification" ([storefront schema L259](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/storefront-graphql-schema/2026-10/items.jsonl?plain=1#L259)). That is Relay, *GraphQL Global Object Identification Specification*, undated, https://relay.dev/graphql/objectidentification.htm.
3. **Needed before any area?** **Reading:** in part.
   - The ID scheme is needed before the first area exposes anything. Shopify still carries a second ID on types that "directly correspond to a REST Admin API resource" ([admin schema L1886](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L1886)).
   - The version calendar can wait until outside apps depend on the API. Shopify's API was in use by 2011: "Developing Shopify Apps, Part 2: Exploring the API" ([blog L429](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L429)). Versions came in 2019: "In April of this year, we released the first official version of our API." ([blog, 2019, L315](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L315)).
4. **Claims the evidence doesn't bear out.**
   - *One graph*, for the admin, apps and storefronts alike. The cited line is the Admin API's root alone: "This acts as the public, top-level API from which all queries must start." ([admin schema L2804](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L2804)). See point 1.
   - *The admin uses the same API.* The cited line says "The admin calls its own API as persisted GraphQL operations" ([READING L41](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/docs/READING.md?plain=1#L41)), at areas such as "capital/<store>" and "billing/shop/<id>/graphql" ([READING L43-L44](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/docs/READING.md?plain=1#L43-L44)). **Reading:** that shows the admin calls GraphQL, not that it calls the API apps call. The line is *the capture's* guide, not Shopify's words.
   - Everything else holds: the quoted lines, the 3,716 types and the 221 types that carry `Node` (counted).

## 7. Money

1. **Wording.** Nothing found. The question lists its own options: *as what kind of number, with which currency, and in whose currency (the shop's, the buyer's, or both)*.
2. **Practice citations.**
   - Fowler, *Patterns of Enterprise Application Architecture*, Addison-Wesley, 2002, the Money pattern, https://martinfowler.com/eaaCatalog/money.html. Real. The catalog page says "Monetary calculations are often rounded to the smallest currency unit" and that "it's easy to lose pennies (or your local equivalent) because of rounding errors". The book's method for splitting without losing pennies is cited from memory.
   - ISO 4217:2015, *Codes for the representation of currencies*. Real. Its maintenance agency says "SIX is the official Maintenance Agency of these currency codes under ISO 4217" (SIX, *Data standards*, https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html). The 2015 edition is cited from memory, because iso.org refused my fetch.
   - Shopify's own currency list is wider than ISO 4217. It says "Supported codes include standard ISO 4217 codes, legacy codes, and non- standard codes." ([web pixels reference L21](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/web-pixel-events/shopify.dev@2026-09-30/items.jsonl?plain=1#L21)). Its admin list holds "USDC" and "KID" ([admin schema L985](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L985)), and the list changes with API versions: 2027-01 marks ANG "Use XCG instead." ([admin schema 2027-01, L1008](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2027-01/items.jsonl?plain=1#L1008)).
3. **Needed before any area?** **Reading:** before the first area that holds an amount, which is nearly every commerce area. 119 types have a field of the type "A precise monetary value and its associated currency." ([admin schema L2266](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L2266)) (counted). A market's currencies and rounding can wait for its setup (decision 5), as the file says.
4. **Claims the evidence doesn't bear out.** Nothing found. The quoted lines hold, and so do the counts of 119 and 66 types (counted).

## 8. Language

1. **Wording.** A mild presupposition. *How is a translation stored* assumes a translation is held apart from its source text, which is Shopify's model: "A localized version of a field on a resource." ([admin schema L3616](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L3616)). **Reading:** a neutral form would be *how is text kept in more than one language*.
2. **Practice citations.**
   - Phillips, Davis (eds.), *Tags for Identifying Languages*, RFC 5646 (BCP 47), September 2009, https://www.rfc-editor.org/rfc/rfc5646. Real, and it says what the file says.
   - Shopify's storefront contract doesn't use BCP 47 tags. Its languages are a closed list of 144 codes (counted), such as "PT_BR" ([storefront schema L212](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/storefront-graphql-schema/2026-10/items.jsonl?plain=1#L212)). A shop's locale in the admin API is a plain "String!" ([admin schema L3157](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L3157)).
   - Esselink, *A Practical Guide to Localization*, John Benjamins, 2000, doi 10.1075/liwd.4, https://www.degruyterbrill.com/document/doi/10.1075/liwd.4/html. Real: a revised edition of the 1998 *A Practical Guide to Software Localization*, with a chapter on internationalization. Not confirmed: that it says *text kept apart from code*. I saw its contents list, not its text.
3. **Needed before any area?** **Reading:** yes, for the rule that no buyer- or staff-facing text is fixed in code. Shopify's account of waiting: "For the past twelve years, we collectively hardcoded thousands and thousands of English strings scattered across all our products oblivious to our future international growth." Since the retrofit: "Due to our cops and linters, we build all new features with translation in mind." ([blog, 2018, L355](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L355)). A market's languages can wait for its setup, as the file says.
4. **Claims the evidence doesn't bear out.** Nothing found. The quoted lines hold, and so do the counts of 30 kinds and 19 types (counted).

## 9. Events and history

1. **Wording.** The question (*How does every area record what happened and who did it, and tell the other areas and apps?*) and the reading's *one shared shape* assume one mechanism for three jobs. **Reading:** Shopify uses a separate mechanism for each:
   - history: "Events chronicle resource activities" ([admin schema L1494](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L1494));
   - apps: webhooks, each subscription tied to an "apiVersion" ([admin schema L3694](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L3694));
   - internal changes: "a log-based change-data capture (CDC) system" ([blog, 2021, L245](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L245)).

   **Reading:** a neutral question would be *what record is kept of each change and of who made it, and how do other areas and apps learn of it?*
2. **Practice citations.**
   - Hohpe, Woolf, *Enterprise Integration Patterns*, Addison-Wesley, 2003, https://www.enterpriseintegrationpatterns.com/. Real, and it says what the file says. The site's patterns include Event Message ("Use an Event Message for reliable, asynchronous event notification between applications.") and Guaranteed Delivery ("Use Guaranteed Delivery to make messages persistent so that they are not lost even if the messaging system crashes."). Publish-Subscribe Channel is cited from memory.
   - CNCF, *CloudEvents* v1.0, October 2019, https://github.com/cloudevents/spec/blob/v1.0/spec.md. Real, and it says what the file says: "CloudEvents is a specification for describing event data in common formats to provide interoperability across services, platforms and systems." The 1.0 date comes from press coverage (https://www.sdxcentral.com/articles/news/cloudevents-hits-1-0-release-gains-cncf-promotion/2019/10/); the spec page gives none.
   - Shopify's evidence shows no such shared envelope. Its webhook headers are its own, such as "X-Shopify-Topic" ([REGISTER L25](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/REGISTER.tsv?plain=1#L25), *the capture's* description).
   - Kent, Souppaya, *Guide to Computer Security Log Management*, NIST SP 800-92, September 2006, https://csrc.nist.gov/pubs/sp/800/92/final. Real, but its subject is computer security logs: "This publication seeks to assist organizations in understanding the need for sound computer security log management." **Reading:** it fits the audit topic, not the history of orders and products that the section cites.
3. **Needed before any area?** **Reading:** in part.
   - Recording each change, with who made it, is needed from the first area, because a change that isn't recorded is lost. On Shopify's old way of extracting data: "any intermediate state is permanently lost" ([blog L245](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L245)).
   - Delivery to apps can wait for extensions (decision 14), and internal streams can wait too. Shopify's 2014 post says "In the early fall our infrastructure team was considering Kafka" ([blog L411](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L411)), and its CDC work began "In mid-2019" ([blog L245](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/engineering-blog/20261031T004307Z-shopify-engineering-posts/items.jsonl?plain=1#L245)).
4. **Claims the evidence doesn't bear out.**
   - *Events are split by shop, like requests and jobs (decision 1, L222)*: there's no pinned link in this section, so I couldn't check it here.
   - *One shared shape*: a reading that Shopify's evidence doesn't show (point 1).
   - Everything else holds: the quoted lines, the 236 topics, and the 230 CLI topics in 72 kinds (counted).

## 10. Custom data

1. **Wording.** The question (*How can merchants and apps add their own fields and types to any area's resources, with definitions…*) assumes Shopify's answer: that they can, on any resource, with both fields and new types, and with definitions. It also goes further than Shopify does:
   - Only 31 types carry "HasMetafields" ([admin schema L1722](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L1722)) (counted), of "2123" object types ([schema meta L25](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/meta.json?plain=1#L25)).
   - Definitions are optional: "Unstructured metafields: These are metafields without definitions." ([Help Center, custom data overview, L12](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/help-center/help.shopify.com@en-ar/md/en/manual/custom-data/overview.md?plain=1#L12)).

   **Reading:** a neutral question would be *may merchants and apps add their own data to the platform's records, or their own kinds of record; if so, on which records, typed how, and who may read and change it?*
2. **Practice citations.** All three are real and say what the file says.
   - Chong, Carraro, Wolter, *Multi-Tenant Data Architecture*, Microsoft, June 2006. I read a copy at https://citus-docs.readthedocs.io/en/v8.0/_static/mt-data-arch.pdf, because the MSDN address returned 404. Its *Extensibility Patterns* are Preallocated Fields, Name-Value Pairs and Custom Columns.
   - Aulbach, Grust, Jacobs, Kemper, Rittinger, *Multi-Tenant Databases for Software as a Service: Schema-Mapping Techniques*, SIGMOD 2008, pp. 1195–1206, doi 10.1145/1376616.1376736. It maps tenants' schemas onto shared tables (from its abstract).
   - Weissman, Bobrowski, *The Design of the Force.com Multitenant Internet Application Development Platform*, SIGMOD 2009, pp. 889–896, doi 10.1145/1559845.1559942. Its abstract, as a web search returned it, describes a "metadata-driven software architecture that enables multitenant applications".
3. **Needed before any area?** **Reading:** only in part: the shared place on resources, and who may read and write it. Shopify added the rest later:
   - metafields go back to the REST API: `Metafield` is among the types that "directly correspond to a REST Admin API resource" ([admin schema L1886](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/admin-graphql-schema/2026-10/items.jsonl?plain=1#L1886));
   - app-owned metafields came in the Summer 2022 edition: "App-Owned Metafields" ([Editions L157](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/editions/www.shopify.com_editions_summer2022_dev/items.jsonl?plain=1#L157), [edition address, meta L8](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/editions/www.shopify.com_editions_summer2022_dev/meta.json?plain=1#L8));
   - metaobjects came in the Winter 2023 edition: "Create custom data models with metaobjects" ([Editions L619](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/editions/www.shopify.com_editions_winter2023/items.jsonl?plain=1#L619)), in "Shopify Editions | Winter ’23" ([Editions L3](https://github.com/Hamza-ye/observed-sh/blob/04de369da9ac84ae530ae80a55749167ff4139d4/structures/shopify/editions/www.shopify.com_editions_winter2023/items.jsonl?plain=1#L3)).
4. **Claims the evidence doesn't bear out.**
   - The reading *every area's resources must accept custom fields the same way*: *the same way* holds (one interface), but *every* doesn't: 31 types (point 1).
   - *It is also one of the access groups an app asks for (decision 4)*: there's no pinned link in this section, so I couldn't check it here.
   - Everything else holds: the quoted lines, and the counts of 31 and 26 (counted).
